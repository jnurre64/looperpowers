## Starting the loop (Codex Goal)

```text
Advance {{project}} toward {{outcome}} until {{human_checkpoint}}, following the shared workflow and all plan, review, current-head CI, merge, playtest, dependency, concurrency and spin-guard rules in {{loop_doc}}. Read {{status_file}} as the shared resume point. Before any project mutation, inspect actual native Goal state, reconcile prior runtimes/workers and acquire or validate this session's codex-goal ownership using the installed loop-start Goal guide. Preserve user changes and unpublished work; publication follows existing authorization and project policy. Continue independent already-designed work within this outcome while dependent work awaits a human. Record evidence and the exact human ask in the shared In flight, Next ready and Awaiting human dashboard. Stop when the defined outcome/checkpoint is reached or only human work remains; use actual supported native controls, never claim a pause without confirmation. Revalidate ownership before every mutation, including after native resume.
```

### Interactive Goal policy

The shared project gates above also apply to Codex. Claude wakeups/monitors and timer hosting
are runtime-specific and are not required for native Goal. The clean-main/publication sequence
for scheduled iterations does not govern merely starting or pausing interactive work. Preserve
branch, staged/untracked files and unpublished commits; record local-only status when publishing
is not authorized. Existing explicit project publication requirements still govern affected
actions. Goal does not grant additional permissions. Pause records native state separately from
project readiness; a paused native Goal retains ownership until verified transfer.
